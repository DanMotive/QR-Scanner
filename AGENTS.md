# QR Scanner — руководство для агентов

## Проект и навигация

Android-приложение на Kotlin и Jetpack Compose с одним модулем `app`.
Интерфейс использует Material 3, сканирование — CameraX и bundled ML Kit,
генерация кодов — ZXing, настройки — Preferences DataStore.
Package и application ID: `com.danmotive.qrscanner`.

Исходники Kotlin находятся в `app/src/main/java/com/danmotive/qrscanner/`:

| Путь относительно этого каталога | Назначение                                                 |
|----------------------------------|------------------------------------------------------------|
| `MainActivity.kt`                | Запуск приложения, тема, локаль и переходы между ними      |
| `ui/QrScannerApp.kt`             | Каркас интерфейса и переключение вкладок                   |
| `ui/screens/`                    | Сканер, генератор, экран «Другое»                          |
| `ui/components/`                 | Переиспользуемые composable-компоненты                     |
| `ui/core/`                       | Вспомогательные функции, генерация QR, сохранение и шаринг |
| `data/SettingsRepository.kt`     | Модель настроек и их хранение                              |
| `ui/settings/`                   | StateFlow настроек, ViewModel и её фабрика                 |
| `ui/theme/`                      | Цвета, типографика и Compose-тема                          |

Перед изменениями проверьте `git status` и относящийся к задаче diff.
Сохраняйте незавершённые изменения других участников. При добавлении поведения
проверяйте вызывающие функции, ресурсы и конфигурацию, которых оно касается.

## Детали, которые важно сохранять

- Пользовательские тексты находятся в `app/src/main/res/values/strings.xml`
  (английский) и `app/src/main/res/values-ru/strings.xml` (русский).
  Добавляйте новые строки в обе локали и используйте ресурсы из интерфейса.
- Настройки проходят через `SettingsViewModel` и `SettingsRepository`.
  Имена enum сохраняются в DataStore как строки; переименование значений или
  ключей `theme_mode` и `language` требует учёта уже сохранённых настроек.
- `QrScannerApp` включает только выбранный экран через `when`.
  Удаление `ScanScreen` из композиции освобождает камеру, ML Kit-клиент
  и executor. При изменении навигации сохраняйте освобождение этих ресурсов.
- В анализаторе камеры каждый `ImageProxy` должен закрываться, включая ранний
  выход. При асинхронном распознавании он закрывается после завершения обработки.
- Язык меняется через `AppCompatDelegate.setApplicationLocales`.
  `MainActivity` учитывает пересоздание Activity, а в манифесте включён
  `autoStoreLocales`. Изменения обработки конфигурации проверяйте вместе
  с переключением языка, восстановлением экрана и переходом из чёрного фона.
- Пути и authority для шаринга задаются совместно в `QrGenerator.kt`,
  `AndroidManifest.xml` и `app/src/main/res/xml/file_paths.xml`.

## Сборка и проверка

- Используйте Gradle Wrapper из репозитория. Его версия задана в
  `gradle/wrapper/gradle-wrapper.properties`, версии библиотек и плагинов —
  преимущественно в `gradle/libs.versions.toml`; часть зависимостей объявлена
  напрямую в `app/build.gradle.kts`.
- `app/build.gradle.kts` — источник настроек SDK, версий приложения,
  ABI-сплитов и подписи. Сейчас `minSdk = 29`, `targetSdk = 37`,
  compile SDK — 37 с minor API 2. Установку SDK сверяйте с обоими workflow.
- CI устанавливает Temurin 21, а `gradle/gradle-daemon-jvm.properties`
  задаёт JVM демона версии 25. Не считайте Java из `setup-java` единственной
  настройкой JVM; разрешение toolchain настроено в `settings.gradle.kts`.

Команды из корня репозитория:

| Проверка            | PowerShell / Windows                          | Linux / macOS                             |
|---------------------|-----------------------------------------------|-------------------------------------------|
| Изменения и пробелы | `git diff --check`                            | `git diff --check`                        |
| Debug APK           | `.\gradlew.bat assembleDebug --console=plain` | `./gradlew assembleDebug --console=plain` |

Debug APK находятся в `app/build/outputs/apk/debug/`.
В репозитории пока нет наборов unit- и instrumented-тестов; успешная сборка
не означает проверку поведения на устройстве. Для изменений сканера проверяйте
разрешения, камеру, импорт фото, вспышку и уход с вкладки. Для генератора —
создание, сохранение и шаринг. Для настроек — тему, язык и повторный запуск.
В отчёте указывайте только фактически выполненные проверки.

## CI, релизы и подпись

- `.github/workflows/ci.yml` собирает debug на push в `main` и pull request,
  затем сохраняет APK как артефакты Actions.
- `.github/workflows/release.yml` запускается по тегу `v*` или вручную
  с обязательным полем `tag`. Checkout выполняется из указанного тега,
  поэтому новые изменения должны попасть в релизный тег, чтобы войти в APK.
- Тег без префикса `v` должен совпадать с `versionName` в `app/build.gradle.kts`.
  Workflow создаёт черновик GitHub Release; публикация — отдельное действие.
- Настроены APK для `armeabi-v7a`, `arm64-v8a`, `x86_64` и universal.
  Релизный workflow прикрепляет их из `app/build/outputs/apk/release/`.
- CI-подпись использует Environment `release` и секреты `KEYSTORE_BASE64`,
  `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`. Путь к декодированному ключу
  передаётся сборке через `KEYSTORE_PATH`. Без него Gradle не назначает
  release signing config; локальный release нельзя считать подписанным.
- Не записывайте ключи и значения секретов в код, документацию или логи.
  `local.properties`, keystore, APK и каталоги сборки исключены из Git;
  не добавляйте их принудительно.

При изменении структуры, сборки или выпуска обновляйте соответствующие сведения
здесь. При расхождении этого файла с конфигурацией проверяйте актуальный код.
